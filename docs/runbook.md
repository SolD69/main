# Runbook: развёртывание сервера с нуля

Порядок действий, отработанный на живом сервере. Отличается от README тем,
что учитывает грабли, которые встречаются на практике: лимиты GitHub,
приватный репозиторий, заблокированные порты, консоль хостера вместо SSH.

Рассчитано на Ubuntu 24.04 LTS, KVM, root-доступ.

---

## Шаг 0. Проверить адрес до того, как что-то настраивать

Самая дорогая ошибка — потратить час на настройку сервера, чей IP недоступен
из вашей сети. Проверяйте сразу после выдачи адреса.

1. `check-host.net/check-tcp?host=<IP>:22` — доступность с узлов в разных странах.
2. `check-host.net/ip-info?host=<IP>` — владелец, ASN, репутация.
3. **Со своей машины, с выключенными прокси и VPN**: `Test-NetConnection <IP> -Port 22`
   (PowerShell) или `nc -vz <IP> 22` (Linux/macOS).

Третий пункт обязателен. Узлы check-host стоят в дата-центрах, где фильтрация
мягче, чем на пользовательских сетях: адрес может отвечать им и не отвечать вам.

| Результат | Диагноз | Действие |
|---|---|---|
| Отвечает всем, включая вас | Адрес чистый | Продолжайте |
| Отвечает миру, но не вам | Блокировка у вашего оператора | Тикет на смену IP |
| Не отвечает никому | Порт закрыт хостером или служба не поднята | Список портов в панели |
| Единичный узел в таймауте | Особенность маршрута оператора | Не блокировка, продолжайте |

## Шаг 1. Проверить, что продали именно то

В VNC-консоли панели хостера или по SSH:

```bash
cat /etc/os-release | head -2      # Ubuntu 24.04
systemd-detect-virt                # kvm, не lxc и не openvz
ip -4 addr show scope global       # белый IP, не 10.x.x.x
nproc; free -h | head -2; df -h /
```

`systemd-detect-virt` должен ответить **kvm**. На контейнерной виртуализации
не включится BBR и не соберётся модуль ядра для AmneziaWG — меняйте тариф
сразу, пока сервер пустой.

Если ОС не Ubuntu — переустановите из панели **сейчас**. Debian 12 годится
для основного канала, но AmneziaWG на нём собирается только из исходников:
готовый PPA существует лишь для Ubuntu.

## Шаг 2. Ключ до защиты, не после

`00-hardening.sh` отключает вход по паролю, только если найдёт
`~/.ssh/authorized_keys`. Ключа нет — оставит пароль и предупредит,
но лучше положить ключ заранее.

С Windows (`ssh-copy-id` там нет):

```powershell
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@<IP> "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

Ключ уже есть — не запускайте `ssh-keygen` повторно: он предложит перезаписать
существующий, и вы потеряете доступ ко всему, куда он прописан.

Проверьте, что `ssh root@<IP>` пускает **без пароля**, прежде чем идти дальше.

## Шаг 3. Если 22-й порт не проходит

Бывает, что SSH не подключается, хотя сервер жив и виден в VNC. Диагностика —
в [`operations.md`](operations.md), раздел про недоступный SSH. Короткий путь,
когда причина в порте: через VNC-консоль

```bash
echo 'Port 2222' > /etc/ssh/sshd_config.d/99-port.conf
sshd -t && systemctl restart ssh && ss -tlnp | grep 2222
```

Дальше подключайтесь `ssh -p 2222`, а хардинг запускайте с указанием порта,
иначе фаервол откроет 22-й и отрежет вам доступ:

```bash
SSH_PORT=2222 bash scripts/00-hardening.sh
rm -f /etc/ssh/sshd_config.d/99-port.conf   # скрипт пишет свой конфиг
```

## Шаг 4. Доставить комплект на сервер

Репозиторий приватный — `git clone` спросит логин, а пароль от аккаунта
GitHub не подойдёт: парольная авторизация для git отключена с 2021 года.
Три рабочих способа, по убыванию удобства:

**Скопировать со своей машины** — токен на сервере не нужен вообще:

```powershell
git clone https://github.com/SolD69/main.git $env:TEMP\vpnkit
scp -P 2222 -r $env:TEMP\vpnkit root@<IP>:/root/vpn
```

**Токен только на чтение**: GitHub → Settings → Developer settings →
Personal access tokens → Fine-grained tokens. Expiration 7 days, Repository
access → только нужный репозиторий, Permissions → Contents: Read-only.
При `git clone` в поле Username — логин, в поле Password — **токен**.
После установки токен отозвать.

**Временно сделать репозиторий публичным**: Settings → Danger Zone →
Change visibility. Быстрее всего, но пока он открыт, его успевают
проиндексировать поисковики, и возврат в private выдачу не чистит.

## Шаг 5. Установка

```bash
cd /root/vpn
SSH_PORT=2222 bash scripts/00-hardening.sh    # SSH_PORT только если меняли порт
bash scripts/01-install-reality.sh
```

Что делает первый скрипт: обновляет систему, включает автообновления
безопасности, поднимает ufw с двумя открытыми портами (SSH и 443), настраивает
fail2ban, отключает вход по паролю при наличии ключа, включает BBR.

Второй ставит Xray, подбирает сайт-маскировку, генерирует ключи, пишет конфиг,
запускает службу и печатает ссылку с QR-кодом.

### Если установка Xray падает с 404 или 429

`raw.githubusercontent.com` лимитирует запросы по адресу, а серверы из
арендованных подсетей делят лимит с соседями по блоку. Скрипт сам перейдёт
на установку из релизного архива — это другой хост с отдельным лимитом.
Ручной эквивалент, если понадобится:

```bash
curl -fsSLO https://github.com/XTLS/Xray-core/releases/latest/download/Xray-linux-64.zip
```

## Шаг 6. Клиенты

```bash
bash scripts/02-add-client.sh phone     # по ключу на устройство
bash scripts/02-add-client.sh --list    # показать все ссылки
bash scripts/02-add-client.sh --remove <имя>   # отозвать доступ
```

Ссылку `vless://` никуда не пересылайте: UUID в ней — это рабочий доступ
к серверу. Скомпрометированный ключ отзывается за две команды — сначала
создайте новый, потом удаляйте старый.

Десктопным клиентам нужен полный конфиг с маршрутизацией:

```bash
bash scripts/06-gen-client-config.sh laptop
```

## Шаг 7. Проверка

**На сервере:**

```bash
systemctl is-active xray && ss -tlnp | grep :443
journalctl -u xray -n 20 --no-pager
```

**Со своей машины, с выключенными посторонними прокси:**

```bash
bash scripts/04-healthcheck.sh <IP>
```

**После подключения клиента** — обязательно обе проверки:

1. `ifconfig.me` показывает **адрес сервера**;
2. `2ip.ru` показывает **ваш настоящий** российский адрес.

Второй пункт подтверждает, что split-routing работает. Если там адрес сервера,
российские сайты идут через VPN, и банки с Госуслугами начнут капчить.

## Работа в VNC-консоли хостера

Консоль передаёт коды клавиш напрямую, а раскладка гостя не совпадает
с вашей. Символы `&`, `|`, `@` приходят искажёнными: `&&` превращается
в `77`, `|` в `\`. Печатать команды руками бесполезно.

- **Вставлять** — только кнопкой **Paste clipboard**.
- **Скопировать наружу нельзя**: буфер работает в одну сторону.

Отсюда два следствия. Ссылку для клиента забирайте не копированием,
а сканированием QR-кода — v2rayN умеет искать QR прямо на экране.
А проверить строку, которую надо сверить с сервером, можно так: вставьте
в консоль `grep` с этой строкой, и сервер сам скажет, совпадает ли.

```bash
grep -qF '<строка>' /usr/local/etc/xray/reality.env && echo совпадает || echo нет
```

## Что остаётся после установки

1. **Перезагрузить**, если `apt upgrade` обновил dbus, микрокод или ядро.
   После перезагрузки проверить, что поднялись и SSH, и `xray`.
2. **Резервный канал**: `bash scripts/03-install-amneziawg.sh`.
3. **Второй сервер** у другого провайдера в другой стране — единственное,
   что реально страхует блокировку первого.
4. **Мониторинг** доступности с российского адреса — см. [`operations.md`](operations.md).
