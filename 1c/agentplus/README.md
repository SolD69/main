# Агент Плюс → УТ 11.5: разбиение заявок по складам

ИП Конышева, расширение РОДЕН, обработка апОбменДанными (модуль объекта). Вставки — в [`split-orders-by-warehouse.bsl`](split-orders-by-warehouse.bsl).

| Требование | Решение |
|---|---|
| Одна заявка Агент+ → несколько ЗаказКлиента по складу группы | Вставки 2–4: строки уже разложены по складам блоком РОДЕН 03.11 (рдн_Склад), заявка режется по складам строк |
| Заказы текущей датой | **Настройка** `ЗагружатьДокументыТекущейДатой` (типовая, только для новых документов). Код не нужен |
| Комментарий `#ОбменАгентПлюс ДАТАВРЕМЯ` | Вставка 1 + функция `рдн_КомментарийОбменаАгентПлюс`; комментарий агента — со второй строки |

## Как работает

- Основной заказ — сам загружаемый документ (ссылка = GUID заявки, по ней подтверждение на телефон). Склад — склад шапки, если по нему есть товар, иначе склад первой строки. Дальше типовой код обрабатывает его как обычно.
- Остальные склады — отдельные заказы с ссылкой `MD5(GUID заявки + GUID склада)`. Пишутся после основного, той же цепочкой: обеспечение, серии, этапы оплаты, валюта, скидки, запись. Повторная загрузка их перезаписывает.
- При повторной загрузке заказ, склада которого больше нет в заявке, помечается на удаление.
- Основной не записался → остальные не пишутся, заявка придёт снова.

## Проверить на копии

- Сумма основного заказа после разбивки (типовой код ставит сумму всей заявки с телефона; УТ должна пересчитать при записи).
- Если не записалась часть, а `ОбновлятьДокументыПриЗагрузке` выключено — повторная загрузка пропустит заявку, часть надо создать руками.
